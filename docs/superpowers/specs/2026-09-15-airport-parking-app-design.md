# 공항 주차장 실시간 현황·추세 앱 설계

작성일: 2026-09-15
상태: 승인됨 (구현 계획 대기)

## 1. 목적

김포·김해·제주공항에 국내선으로 출발할 때, **어느 주차장에 댈지**를 출발 직전에 판단할 수 있게 한다. 휴대폰 브라우저에서 3초 안에 답이 나와야 한다.

같은 공항 안에서도 주차장별 상황이 완전히 다르다는 것이 이 앱의 존재 이유다. 2026-09-15 10:13 실측에서 김포 국내선 제1주차장은 잔여 0면인데 국제선 주차빌딩은 161면이 비어 있었다.

## 2. 측정으로 확정된 사실

설계 판단의 근거다. 모두 2026-09-15 10:15~10:56 실측(165회 호출, 실패 0회)에서 나왔다.

| 사실 | 값 | 설계에 미친 영향 |
|---|---|---|
| 원천 갱신주기 | **정확히 60초** (40회 연속 편차 0) | 수집 주기의 상한이 1분임을 확정 |
| 1분당 변화량 | 중앙값 0대, 평균 0.9대, 최대 12대 | 1분 수집의 실익이 작아 2분으로 결정 |
| 1분간 무변화 비율 | 54% | 위와 같음 |
| 만차 시 카운터 | **고정됨** | 만차 주차장에 추세를 표시하지 않기로 결정 |
| 응답 건수 | `totalCount` 25 (전국 25개 주차장) | 공항코드 없이 1회 호출로 전량 수집 |

### 만차 카운터 고정

김포 국내선 제1주차장(2279면)과 제주 P2장기주차장(488면)은 41분 동안 **주차 대수가 한 번도 변하지 않았다**(무변화 100%). 2279면 주차장에서 평일 오전 41분간 입출차가 0대인 것은 물리적으로 불가능하므로, 점유율이 100%에 닿으면 카운터가 상한에 고정되는 것으로 판단한다. 김해 P2(점유율 99.6%)가 무변화 73%인 것으로 보아 만차에 근접할수록 둔해지는 경향도 있다.

이 때문에 **만차 주차장의 추세는 신뢰할 수 없다.** 고정된 값으로 추세를 계산하면 항상 "변화 없음"이 나오고, 실제로는 대기줄이 빠지고 있어도 그 사실이 드러나지 않는다.

## 3. 사용할 API

`GET https://apis.data.go.kr/B551178/parking-realtime-status/info`

| 파라미터 | 값 | 비고 |
|---|---|---|
| `serviceKey` | 필수 | GitHub Secrets에만 보관 |
| `numOfRows` | 100 | 25건 전량을 1페이지로 |
| `pageNo` | 1 | |
| `type` | json | |
| `schAirportCode` | **사용 안 함** | 생략해야 1회 호출로 전량 수신 |

응답 항목: `aprKor`, `aprEng`, `parkingAirportCodeName`, `parkingFullSpace`(전체 면수), `parkingIstay`(현재 주차), `parkingIincnt`(당일 누적 입고), `parkingIoutcnt`(당일 누적 출고), `parkingGetdate`, `parkingGettime`.

### 혼잡도 API를 쓰지 않는 이유

`parking-congestion/info`는 같은 25개 주차장을 같은 단위로 주지만, 제공 필드가 `parkingCongestion`(만차/혼잡/원활)과 `parkingCongestionDegree`(퍼센트 문자열)로 다르다. 그런데 이 값들은 실시간 API의 `parkingIstay / parkingFullSpace`로 그대로 계산된다(실측 교차검증: 김포 국제선 주차빌딩 367/567 = 64.73%, 문서 표기와 일치). 반면 실시간 API에만 있는 입·출고 누적은 혼잡도 API로 대체할 수 없다.

즉 혼잡도 API는 정보량이 더 적으면서 의존만 하나 늘린다. 등급 판정은 직접 한다(§6).

## 4. 아키텍처

```
[GitHub Actions]  30분마다 트리거 → 각 실행이 35분간 2분 간격 수집
      │ serviceKey (Secrets)
      ▼
  parking-realtime-status/info   (1회 호출 = 25개 주차장)
      │
      ▼
  raw/YYYY-MM-DD.jsonl.gz    원본 2분 해상도. 앱은 읽지 않음
      │
      ├─→ app/latest.json         최신 9곳 + 1시간 증감      ~4KB
      └─→ app/today-<CODE>.json   공항별 오늘 곡선 (5분 격자) ~8KB
      │ git commit
      ▼
[GitHub Pages] 정적 서빙
      ▼
[휴대폰 브라우저]
```

### 수집 주기를 2분으로 정한 근거

원천은 60초마다 갱신되지만 1분 변화량이 평균 0.9대(중앙값 0대)라, 1분과 2분의 곡선 차이는 화면에서 구분되지 않는다. 2분이면 일 720회로 트래픽 한도가 1,000이든 10,000이든 안전하다. 최신성 손실은 최대 2분이다.

### 겹침 수집과 중복 제거

GitHub Actions의 `schedule` 트리거는 부하에 따라 지연되거나 건너뛸 수 있다. 이를 흡수하기 위해 **트리거 간격(30분)보다 실행 시간(35분)을 길게 잡아 의도적으로 겹치게** 한다.

중복은 **`parkingGetdate + parkingGettime`(원천이 스스로 찍은 시각)을 키로 제거**한다. 같은 스냅샷을 두 번 수집해도 같은 키에 덮어쓰므로 데이터가 오염되지 않는다. 이 설계 덕분에 스케줄 지연이 데이터 공백으로 이어지지 않는다.

주의: 실측 결과 **같은 응답 안에서도 주차장마다 초가 1초씩 다르다**(10:13:03과 10:13:04 혼재). 대표 타임스탬프는 **최댓값**을 쓴다. 첫 행의 값을 쓰면 행 순서가 바뀔 때 갱신이 없어도 변화로 오인한다.

### 보관 정책

| 대상 | 해상도 | 보관 |
|---|---|---|
| `raw/` | 2분 | 90일 (gzip, 약 200KB/일) |
| `history/` | 5분 | 영구 — 2단계(요일·시간대 패턴)의 학습 데이터 |
| `app/` | 5분 | 당일분만 |

수집은 전국 25곳 전부 하고, 앱으로 내보낼 때만 3개 공항으로 거른다. 좁혀서 수집하려면 `schAirportCode`로 3회 호출해야 해서 오히려 트래픽이 3배가 되고, 과거 데이터는 소급 생성이 불가능하기 때문이다.

## 5. 범위

**포함**: 김포(GMP)·김해(PUS)·제주(CJU)의 여객 주차장 9곳.

| 공항 | 주차장 |
|---|---|
| 김포 | 국내선 제1주차장, 국내선 제2주차장, 국제선 주차빌딩, 국제선 지하 |
| 김해 | P1 여객주차장, P2 여객주차장, P3 여객(화물) |
| 제주 | P1주차장, P2장기주차장 |

**제외**:
- 인천국제공항 — 별도 기관(IIAC)의 다른 API가 필요하다
- 화물 전용 주차장 — 김포 화물청사는 순환버스가 보세구역을 경유해 여객 이용에 부적합하다. 제주 화물주차장도 같은 이유로 뺀다
- 주차요금 비교 — 별도 API가 필요하고, 판단에 미치는 영향이 잔여면수·접근성보다 작다
- 도착시각 예측 — 요일·시간대 패턴이 쌓인 뒤의 3단계 과제다

## 6. 표시 규칙

### 등급

면수와 비율을 함께 본다. 비율만 쓰면 작은 주차장이 여유해 보이고, 면수만 쓰면 큰 주차장이 과대평가된다.

| 등급 | 조건 |
|---|---|
| 만차 | 잔여 ≤ 0 |
| 혼잡 | 잔여 ≤ 30면 **또는** 점유율 ≥ 95% |
| 보통 | 점유율 ≥ 80% |
| 여유 | 그 외 |

### 정렬

`(만차 여부, 셔틀 필요 여부, 잔여면수 내림차순)` 순으로 정렬한다.

접근성을 잔여면수보다 앞에 두는 이유는, 도보권이 비어 있으면 셔틀 주차장은 볼 이유가 없기 때문이다. 잔여면수 단일 정렬로는 셔틀 주차장이 도보권보다 위로 올라온다. 만차는 선택지가 아니므로 맨 뒤로 보낸다.

점수화는 하지 않는다. 순서의 이유를 사용자가 납득하지 못하면 앱을 신뢰하지 않는다.

### 추세

- 표시 단위: 최근 1시간 순증감(대수) + 오늘 0시부터의 곡선
- **규모 대비 1% 미만(최소 3대)의 변화는 방향을 단정하지 않고 "큰 변화 없음"으로 표기한다.** 2005면 주차장의 12대 증가를 상승 추세로 보여주면 없는 추세를 만들어내는 것이다
- **만차 주차장은 추세를 표시하지 않고 "만차 — 입출차 정보 없음"으로 대체한다** (§2 근거)

### 곡선

스파크라인의 **최소 진폭을 총 주차면의 5%로 고정**한다. 각 주차장의 자기 최소·최대로 정규화하면 1763면 중 15대(0.8%) 변화가 화면 가득 출렁이는 그래프가 되어 오판을 부른다.

### 청사 그룹

김포는 국내선청사와 국제선청사가 떨어져 있어 순환버스로 이동해야 한다. 주차장을 청사별 섹션으로 나누고, 이용 청사가 아닌 쪽에는 셔틀 배차간격을 함께 표시한다. 김해와 제주는 청사가 하나여서 해당하지 않는다.

### 접근성 메타데이터

`data/lot_access.json`에서 관리한다. 실시간 API로 오지 않는 정적 정보이고 거의 변하지 않는다.

**조인 키는 `aprKor` + `parkingAirportCodeName`이며, 한 글자라도 다르면 접근성 정보가 조용히 사라진다.** `probe/check_join.py`가 실제 응답과 대조해 검증한다.

각 항목에 `confidence`를 둔다(`official` / `secondary` / `user` / `unverified`). `unverified`인 항목은 구체적 수치를 표시하지 않고 "도보권"까지만 쓴다.

확인된 셔틀 정보:

| 공항 | 배차 | 출처 |
|---|---|---|
| 김해 | 10분 간격, 05:00~22:50, 무료 | 공항 공식 |
| 김포 (여객청사행) | 12~15분 | 나무위키 — 재확인 필요 |

## 7. 에러 처리

**원칙: 오래된 데이터를 최신인 척 보여주지 않는다.** 이 앱에서 가장 위험한 실패는 앱이 죽는 것이 아니라, 만차인 주차장을 여유로 표시해 헛걸음시키는 것이다.

| 상황 | 감지 | 화면 |
|---|---|---|
| 수집기 실패 | `latest.json` 타임스탬프 경과 | "N분 전 정보" 주황색, 15분 초과 시 경고 배너 |
| API 장애 | `resultCode ≠ 00` | 직전 정상값 유지 + 위 경고 |
| 원천 갱신 정지 | `parkingGettime`이 10분 이상 불변 | "공항 측 정보 갱신이 멈췄습니다" |
| 일부 주차장 누락 | 수신 건수 < 기대 건수 | 해당 카드만 "정보 없음" — **숨기지 않는다** |
| 전체 면수 0 | `parkingFullSpace == 0` | 점유율 계산 생략, "운영 정보 없음" |

마지막 두 항목은 실측에서 나온 실제 사례다. 청주 여객 제3주차장은 전체 면수가 0이라 그대로 나누면 0으로 나누기가 발생한다. 대상 3개 공항에는 현재 없지만 방어는 공통 코드에 둔다.

일부 누락을 조용히 성공 처리하면 앱에서 주차장이 사라져 사용자가 존재 자체를 모르게 된다.

## 8. 테스트

가이드 문서의 응답 예제와 `probe/refresh_log.jsonl`의 실측 데이터를 픽스처로 쓴다.

**파서**
- 문서 샘플 → 25행 정상 파싱
- `items`가 단건 dict로 올 때 리스트로 정규화
- 인증 실패 봉투(`OpenAPI_ServiceResponse`) 처리
- 비JSON 응답 시 원문 보존

**집계**
- 등급 경계값: 잔여 0 / 1 / 30 / 31면, 점유율 79.9% / 80% / 94.9% / 95%
- 전체 면수 0일 때 0으로 나누기 미발생
- 대표 타임스탬프가 최댓값인지 (행 순서를 섞어도 동일 결과)
- `src_ts` 중복 스냅샷이 덮어쓰기로 처리되는지

**추세**
- 규모 1% 미만 변화 → "큰 변화 없음"
- 만차 → 추세 자체가 출력되지 않음
- 데이터 1점뿐일 때(수집 시작 직후) 추세 미표시
- 5분 다운샘플에서 마지막 값이 누락되지 않음

**표시**
- 정렬: 셔틀 주차장이 도보권보다 위로 올라오지 않음
- 정렬: 만차가 맨 뒤
- 스파크라인 최소 진폭이 적용되어 미세 변화가 과장되지 않음
- 타임스탬프를 과거로 조작하면 경고 배너가 뜸

**메타데이터**
- `check_join.py`: 3개 공항 응답의 모든 주차장이 `lot_access.json`에 존재
- `confidence: unverified`인 항목에 구체적 분 단위가 표시되지 않음

## 9. 미결 사항

| 항목 | 영향 | 처리 |
|---|---|---|
| 일일 트래픽 한도 미확인 | 없음 — 2분(720회/일)은 어느 한도에서도 안전 | 확인되면 1분 상향 재검토 |
| `walk_min` 5곳 미확인 | 낮음 — "도보권"으로 표기 | JSON 값만 채우면 반영. 코드 변경 불필요 |
| git 저장소 미생성 | **높음 — GitHub Actions의 전제** | 구현 1단계에서 `git init` 및 원격 저장소 연결 |

저장소는 **공개**여야 한다. GitHub Actions 무료 실행 시간이 무제한이고 Pages를 쓸 수 있기 때문이다. 다루는 데이터가 전부 공공데이터라 공개에 문제가 없다. `serviceKey`는 Secrets에만 두고 커밋하지 않는다.
